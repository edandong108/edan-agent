# 决策史（ADR）

> 每条决策记录：背景 → 选择 → 理由 → 影响。新决策追加在后，不修改历史条目（推翻时新增一条引用旧编号）。

## D1 双数据源分工：Gauss 主库 + MySQL 副库

- **背景**：平台既有 GaussDB（udp_etl）承载台账类数据，调度侧（job/实例/队列）历史上在 MySQL。
- **选择**：主库（Gauss）= 平台自有数据（表登记、探查、实时流、台账、告警）；副库（MySQL）= 调度侧数据（job、job_instance、schedule_queue）。
- **理由**：调度链路既有依赖 MySQL 不动，新业务数据落 Gauss 顺应集团库选型；避免跨库迁移风险。
- **影响**：Mapper 分 `dao/primary` 与 `dao/secondary` 两包；**新功能先判数据归属再选包**；队列 SLA 类查询一律走副库。跨库 JOIN 禁止，需 Java 侧聚合（参考 QueueAnalysisServiceImpl 按天加载+切片聚合）。

## D2 菜单不由前端写死：IAM 下发 + glob 映射

- **背景**：门户是集团统一入口，菜单/权限由 IAM/4A 与 data-permission 服务统管。
- **选择**：菜单数据由 IAM 动态下发；前端用 `import.meta.glob` 把路由名映射到 `views/**/index.vue`。
- **理由**：新页面上线不改前端代码，只需建目录 + IAM 配菜单；权限收敛在平台侧。
- **影响**：新增页面 = `views/<域>/<页面>/index.vue` + IAM 菜单配置；路由名与目录名保持约定；本地 mock 菜单见 `mock/portal-local.ts`。

## D3 任务运维合并为双 Tab 壳页

- **背景**：SLA 迭代（2026-09-10，后端 00cd149 / 前端 4f11ac5）新增队列状态、队列分析两个能力；若各开菜单会打散运维视角。
- **选择**：任务运维页作为壳页，以 Tab 承载「队列状态 + 队列分析」（views `dataExchange/taskOperations`），共用一个菜单项。
- **理由**：运维场景下"看当前队列"与"分析历史积压"是连续动作，同页切换成本最低；菜单数不膨胀。
- **影响**：后续运维观测类功能优先评估能否并入该壳页 Tab，而非新增菜单。
