一、背景与目标

1.1 背景

SLA 保障第一阶段已实现队列调度模型（entry.py 提交、schedule_queue 排队、可配置最大并发 K、手动出队），但队列状态对运维不可见：积压、等待时长、僵尸实例、SLA 达标率均无页面呈现，运维只能翻执行日志逐条排查。

1.2 目标

目标说明
队列状态可见当前/历史时刻的排队、执行、僵尸瞬时分布
SLA 可量化按天 5 分钟切片，高优/普通达标率、排队深度、等待分位、吞吐、僵尸检出
事后可复盘回看某天积压何时形成、谁拖后腿、入口/出口归因

1.3 非目标（一期不做）

自动告警推送、自动重跑/杀僵尸（僵尸不联动动作）、导出功能（快照页与分析页均不做）、跨天对比、按表单独设置 SLA 基线（一期固定 30min，后续演进）、sla_priority 参与排序（一期仅展示）。

SLA 基线演进说明：原始 SLA 方案中每张表基于历史数据情况设定各自基线值。一期为简化实现统一固定 30min；后端聚合接口预留 baseline 入参（默认 30min），后续支持按表配置时只需扩展基线来源（如读 job 表的 SLA 基线字段或独立配置表），接口与前端无需大改。

三、数据模型与口径

3.1 schedule_queue（底层老师已建表，本方案只读）

依据 SLA 方案 7.5，schedule_queue 为 append-only 历史表，每条记录代表一次排队生命周期。需与底层老师确认字段，预期字段口径如下：

字段含义本方案用途
id自增主键—
job_id作业IDJOIN job 取湖表名
sla_priority优先级 0=普通 / 1=高优展示标签（一期不参与排序）
submit_time入队时间排队等待时长起点、FIFO 排序键
finished_at离队时间（提交/取消）排队区间终点，NULL 表示仍在队
statusQUEUED / SUBMITTED / ...区分排队中/已提交
待确认：实际字段名与 status 枚举值需与底层老师对齐；若 finished_at 命名不同（如 dequeue_time），口径相应调整。

3.2 job_instance（已存在，复用）

现有 JobInstance 实体字段：id, jobId, status(PENDING/RUNNING/SUCCESS/FAILED), heartBeatenAt, createdAt, updatedAt。本方案复用，取 createdAt（实例创建）、heartBeatenAt（心跳）、status（实例状态）。

3.3 job（已存在，复用）

取湖表名：出湖取 source_schema.source_table，入湖取 target_schema.target_table（与台账页一致）。

3.4 三态口径（快照重建）

状态判定（快照时间 T）数据来源
排队中status=QUEUED 且 submit_time ≤ T 且 (finished_at IS NULL OR finished_at > T)schedule_queue
执行中经队列提交（SQ status=SUBMITTED）且对应实例 created_at ≤ T 且未进终态schedule_queue JOIN job_instance
僵尸执行中且 T − heart_beaten_at > 阈值（100s）job_instance 心跳实时派生

去重：同一 jobId 跨集合只归一侧（执行中 > 排队中 > 僵尸）；集内按 jobId 去重取最新实例。

四、后端设计

4.1 新增实体与 Mapper

包路径遵循项目既有结构（dao/entity、dao/secondary/mapper，MYSQL 走 secondary 数据源）。

// dao/entity/ScheduleQueue.java （新增，只读）
@Data @Builder @NoArgsConstructor @AllArgsConstructor
public class ScheduleQueue {
    private Long id;
    private Long jobId;
    private Integer slaPriority;   // 0 普通 / 1 高优
    private Timestamp submitTime;
    private Timestamp finishedAt;
    private String status;          // QUEUED / SUBMITTED / ...
}
// dao/secondary/mapper/ScheduleQueueMapper.java （新增，注解式，与 JobInstanceMapper 风格一致）
@Mapper
public interface ScheduleQueueMapper {

    // 快照：某时刻仍在队的排队记录
    @Select("SELECT * FROM schedule_queue WHERE status='QUEUED' " +
            "AND submit_time <= #{t} AND (finished_at IS NULL OR finished_at > #{t}) " +
            "ORDER BY submit_time ASC")
    List<ScheduleQueue> listQueuedAt(Timestamp t);

    // 快照：某时刻已提交未终态的记录（用于关联实例）
    @Select("SELECT * FROM schedule_queue WHERE status='SUBMITTED' " +
            "AND submit_time <= #{t} AND (finished_at IS NULL OR finished_at > #{t})")
    List<ScheduleQueue> listSubmittedAt(Timestamp t);

    // 分析：某天全部记录（用于切片聚合）
    @Select("SELECT * FROM schedule_queue WHERE submit_time >= #{dayStart} " +
            "AND submit_time < #{dayEnd}")
    List<ScheduleQueue> listByDay(Timestamp dayStart, Timestamp dayEnd);
}

4.2 QueueStatusService（快照重建）

核心方法：QueueStatusSnapshotDto snapshot(Timestamp t, boolean now)。

  1. 取 listQueuedAt(t) → 排队中明细
  2. 取 listSubmittedAt(t) → 关联 JobInstanceMapper（按 jobId 取 created_at ≤ t 的最新实例）→ 执行中
  3. 执行中按 t - heartBeatenAt > 100s 派生僵尸，从执行中拆出
  4. JOIN JobMapper 补湖表名、sla_priority 标签
  5. 跨集合去重（执行中 > 排队中 > 僵尸），集内按 jobId 取最新实例
  6. 组装三段统计卡 + 明细表返回

当前时刻：t = 数据库 NOW()（避免应用时钟漂移）；历史时刻：入参校验 t <= NOW()，未来时间报错。

4.3 QueueAnalysisService（切片聚合）

核心方法：QueueAnalysisDto analyze(String day, String priority, String slice, Integer baseline)，slice=5min（288 片）/1hour（24 片），baseline 默认 30（分钟，一期固定，预留按表配置扩展）。

  1. 取 ScheduleQueueMapper.listByDay + JobInstanceMapper 当日实例
  2. 按切片边界聚合：每切片末排队深度、执行并发、入队/提交/完成数
  3. 等待时长分位：切片内离队作业 (finished_at − submit_time) 的 P50/P90/P99
  4. SLA 达标率：高优/普通分别统计超 baseline 占比
  5. 僵尸检出：每切片内心跳停摆超阈值的实例数（只展示，不联动动作）
  6. TopN：当日等待时长最久的作业（按优先级可筛，Top 10 可分页）
性能策略：288 片数据量小，建议后端一次性聚合返回，前端只渲染；避免前端逐切片请求。当日数据量大时按 submit_time 加索引（底层老师建表时确认）。

七、风险与对策

风险对策
schedule_queue 非 append-only / 字段语义与预期不符开发前与底层老师逐字段对齐，确认 status 枚举、finished_at 语义、是否真 append-only
历史快照重建口径偏差以方案 7.5 区间覆盖法为准，联调时用已知事件回放校验
5 分钟聚合当日查询慢后端一次性聚合；确认 submit_time 索引；必要时按天缓存
僵尸"已自愈"展示缺数据一期不展示自愈，只展示僵尸检出数
10s 自动刷新压元数据库默认关闭，用户手动开；评估后可调 15-30s
时钟漂移当前态以数据库 NOW() 为准，不用应用本地时间
