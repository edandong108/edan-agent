跨中心同步 — 评审一页纸

数据交换中心 · 应用层 · 2026-09-11 · 状态：待评审 · 原始需求原件：核心文档/跨中心同步功能/需求/【统一数据开发平台】需求说明书-跨集群.pdf · 产品交互稿（过程稿，未入仓）：核心文档/跨中心同步功能/方案/跨中心同步-产品交互稿.html （PDF 不入本仓；链路调研页仅作背景，不作为本页施工图）

一句话定位：链路层把湖内搬运任务写入现有 MySQL job 表（实例为 bigdata_hive，其余与普通任务同类）。 应用层只做一件事——业务入湖列表不再混入这类任务，并在任务管理增加并列入口「跨中心同步」供平台/运维查看、执行、停止。 不新建同步引擎、不改入湖表单、不把 DistCp/互信做成产品选项。

一、解决什么问题

痛点说明
业务入湖被污染 现网入湖/出湖靠 source_instance 是否等于 hive 二分。湖内搬运（bigdata_hive ↔ hive）会落入入湖或出湖：业务打开「入湖」会看到不是自己源系统的任务。
湖间任务无处安放 搬运任务需要执行/停止/历史，但不是入湖也不是出湖（出湖目标是 DWS/CK/SFTP）。继续塞在入湖里，责任边界和排查路径都错。
原始 PDF 不可直接开发 前 8 页是 Hive2Hive/DistCp/SFTP/互信验证；后 3 页 UI 与阶段目标互相矛盾（「入湖页不变」却要三种集群标签；「双向集群」实际是两跳；「台账」又能执行删除）。本页按产品判断收口，不按截图施工。

二、做什么（任务管理三分，不新开菜单）

入口：【数据交换】→ 现有 任务管理（taskManagement/index.vue）。 顶部在「入湖 / 出湖」旁增加第三按钮 跨中心同步。 不新开 IAM 菜单；不在入湖内再套「源→湖 / 湖↔湖」Tab；不叫「台账」。

入湖（业务）

源系统 → 北中心 Hive。列表必须干净。

新建/编辑页面 本期不变。

出湖（分发）

Hive → DWS / CK / SFTP。规则不变。

不得混入湖到湖搬运。

跨中心同步（运维）

湖实例 → 湖实例。项目隔离。

操作复用：查看、执行、停止、更多（删除、执行历史、调试日志）。

列表须能看出搬运方向（源实例 → 目标实例，或北同城 / 北中心可读名）。

三、识别口径（湖间任务怎么判）

建议规则：源实例与目标实例都属于湖实例集合 → 跨中心任务；否则按现网规则归入湖或出湖。 本期湖实例集合暂定 { hive, bigdata_hive }（大小写不敏感）。方向不写死，以 job 行字段为准。

情形归类出现在
源 = 业务库，目标 = hive入湖仅入湖
源 = hive，目标 = DWS/CK/SFTP 等出湖仅出湖
源/目标均为 hive 或 bigdata_hive跨中心同步仅跨中心同步
待链路确认（不编造）：请提供 1 条真实或约定的 job 样例（id / source_instance / target_instance / source_schema / source_table / target_schema / target_table）。 本页按「两端都是湖实例」写验收；若实际只在其中一端写 bigdata_hive，技术方案按样例改识别 SQL，产品三分不变。

四、需求与验收（当 X 时系统应 Y）

编号 需求 验收标准
R1 入湖列表隔离
  1. 当项目下存在湖间 job（两端均为湖实例）时，入湖分页 不得 返回该 jobId。
  2. 当仅存在普通入湖 job 时，入湖列表条数与改前一致（回归）。
  3. 可观察：同一 projectId 下用入湖查询 vs 直接查 job 对照。
R2 出湖列表隔离
  1. 当存在 hive → bigdata_hive（或反向两端皆湖）的 job 时，出湖分页 不得 返回该 jobId。
  2. 普通出湖（目标为 DWS/CK/SFTP）仍出现在出湖。
R3 跨中心列表
  1. 当用户切换到「跨中心同步」时，只看到本项目下的湖间 job；默认不串项目。
  2. 当无此类 job 时，列表为空，不报错。
  3. 列至少含：任务 ID、源实例、源库/表、目标实例、目标库/表、创建人、最近执行状态；「责任人」若出现则改为创建人。
  4. 任务 ID 与入湖同一套 job.id，不另编码。
R4 运维操作复用
  1. 当对跨中心任务点查看 / 执行 / 停止 / 删除 / 执行历史 / 调试日志时，行为与现网任务管理同类操作一致（含权限码）。
  2. 当任务正在 RUNNING 时，执行按钮禁用规则与入湖一致。
  3. 不提供「去出湖」；不提供数据比对（湖到湖本期不做）。
R5 入湖表单不变
  1. 当用户新建/编辑入湖任务时，页面字段与改前一致，不新增目标集群选择。
  2. 入湖去向实例仍为 hive（北中心）。
R6 队列运维不受损
  1. 当湖间任务进入 schedule_queue 时，任务运维（队列状态/分析）仍能看到该作业——运维视角需要，不从队列里抹掉。
  2. 可观察：队列快照中的 jobId 仍能关联到跨中心列表中的同一条任务。

五、边界（先做 / 后做 / 不做）

项说明
本期做R1–R6：三分列表、隔离、复用运维操作、入湖表单不动、队列仍可见
后做入湖「更多 → 新增跨中心同步」派生创建；入湖列表集群标签/关联子任务；入湖选目标集群；入湖双写
不做DistCp / SFTP / Kerberos 互信 / YARN 路由作为门户能力；CDC / 准实时 flush 配置；「双向集群」标签与浮窗
不做本系统不负责写入湖间 job（链路层已写入 job）；不新建 job 表、不改执行端 Python
否决 PDF入湖内双 Tab +「跨中心同步台账」命名；任务设置「置灰」与「可填」并存的弹窗稿；把 target_cluster flag 暴露给用户

六、依赖与影响

项说明

链路依赖湖间任务已由链路写入 job，且实例约定为 bigdata_hive（样例待确认）
